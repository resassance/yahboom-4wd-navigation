# Короткая памятка на 13 октября

Цель: проверить более плотный обзор и первый автоматический объезд; определить входы рабочих ИК-датчиков. Взять ноутбук и зарядку, рулетку/линейку, малярную ленту, телефон. Цветные препятствия пока не нужны.

## 1. Передать новую версию — на ноутбуке

Использовать новый архив `yahboom-4wd-navigation-2026-10-13.zip`. Старый архив от 6 октября и `git clone` сейчас не содержат локальных правок.

Распаковать архив. Через файловый менеджер открыть `sftp://LOGIN@IP/`, заменив логин и адрес. Скопировать извлечённую папку на робота как `yahboom-4wd-navigation-20261013`, отдельно от прошлой версии. Можно передать всю папку; обязательны `robot_navigation.py`, `navigation.py`, `robot_config.json` рядом друг с другом.

Подключиться из терминала ноутбука:

```bash
ssh LOGIN@IP
```

Дальше команды выполняются на роботе:

```bash
cd ~/yahboom-4wd-navigation-20261013
date
```

Проверить часы: на прошлых логах была дата 7 марта. Не запускать одновременно другие программы, работающие с GPIO.

## 2. Положение дальномера и обзор — 15 минут

```bash
cp robot_config.json robot_config.local.json
nano robot_config.local.json
```

Длина 24 см и ширина 18,5 см уже внесены. Измерить расстояние от задней границы корпуса до передней поверхности излучателя. Вычесть 12 см и записать результат в `sensor_forward_offset_cm` вместо `null`. Это единственный обязательный недостающий геометрический размер. Положительное значение означает положение впереди центра; излучатель по описанию находится внутри корпуса.

В nano: Ctrl+O, Enter — сохранить; Ctrl+X — выйти.

```bash
sudo python3 robot_navigation.py --mode distance --cycles 10
sudo python3 robot_navigation.py --mode scan --max-seconds 60
```

Обзор теперь содержит девять направлений. Проверить, что 90° смотрит вперёд и направления соответствуют прежним. Во время обзора корпус неподвижен.

## 3. Найти рабочие ИК-входы — 20 минут

Начать с прежних входов:

```bash
sudo python3 robot_navigation.py --mode ir --ir-pins 12,17 --max-seconds 30
```

Смотреть `levels` и `changed_pins`. По очереди воздействовать на каждый физический датчик. Затем, после сверки подключения нижней платы, проверить предполагаемую группу линии:

```bash
sudo python3 robot_navigation.py --mode ir --ir-pins 3,5,4,18 --max-seconds 30
```

Для датчиков линии поднести белую поверхность, затем чёрную полосу на той же высоте. Записать, какой GPIO изменился, какой физический датчик проверяли и какие уровни были на белом/чёрном. Номера — BCM, не физические контакты.

Если по реальному подключению нужен другой набор, указать его через `--ir-pins`; номера не подбирать случайно. Режим настраивает выбранные контакты как входы. Данные проекта другой группы 7/6 не означают, что они подходят нашей сборке.

Этот режим только опрашивает входы, не двигает колёса или сервопривод и не меняет защиту автоматического режима. `--use-ir` пока не включать: прошлые 0/0 и полярность ещё не объяснены.

## 4. Проверить прямой проезд — 15 минут

На пустом участке с запасом до края стола:

```bash
sudo python3 robot_navigation.py --config robot_config.local.json --mode drive --drive-seconds 0.5
```

Сделать три повтора с одной разметки, измерить путь и боковой уход. Если едет прямо, поправки оставить 0. Если систематически уходит:

- Влево: попробовать уменьшить `right_drive_trim_pwm` до −1 или −2.
- Вправо: попробовать уменьшить `left_drive_trim_pwm` до −1 или −2.

Менять только одну поправку и повторять исходную постановку. Эти изменения не затрагивают мощность поворотов. Не переводить прежнюю калибровку в чужие коэффициенты см/с.

Проверить один поворот вправо и влево на свободном месте:

```bash
sudo python3 robot_navigation.py --mode turn --turn-deg 45
sudo python3 robot_navigation.py --mode turn --turn-deg -45
```

Режимы `drive`/`turn` выполняют команду напрямую, без разрешения дальномера. Ctrl+C — остановка, человек должен иметь доступ к выключателю питания.

## 5. Решение без движения, затем объезд — 50 минут

Поставить одну пачку с широкими проходами. Начать с неподвижной проверки:

```bash
sudo python3 robot_navigation.py --config robot_config.local.json --mode plan --max-seconds 60
```

В событии `navigation_plan` смотреть `action`, `angle_deg`, `reason`, расстояния и оценки сторон. Переставить препятствие ближе к левому/правому бортику и повторить. При закрытых проходах ожидать `stop`. Корпус в `plan` не движется; это проверка первого решения, а не всего будущего маршрута.

Если решение соответствует постановке:

```bash
sudo python3 robot_navigation.py --config robot_config.local.json --mode auto --max-seconds 120
```

Для первых запусков оставить большие проходы. Снять полный маршрут неподвижной камерой сверху. Зафиксировать сторону объезда, минимальный зазор и направление после возврата. Если остановился, сохранить причину; не уменьшать запас только ради проезда. Обзор стал медленнее, во время него робот стоит.

## 6. До ухода — 10 минут

Сохранить все папки `logs/`, `robot_config.local.json`, фактически использованные Python-файлы, фото и видео. Для каждого ролика назвать номер опыта и записать соответствующую папку логов.

В отдельном терминале на ноутбуке:

```bash
mkdir -p ~/Documents/robot-lab-20261013
scp -r LOGIN@IP:~/yahboom-4wd-navigation-20261013/logs ~/Documents/robot-lab-20261013/
scp LOGIN@IP:~/yahboom-4wd-navigation-20261013/robot_config.local.json LOGIN@IP:~/yahboom-4wd-navigation-20261013/robot_navigation.py LOGIN@IP:~/yahboom-4wd-navigation-20261013/navigation.py ~/Documents/robot-lab-20261013/
```

Можно забрать те же файлы через SFTP мышкой. Нужны полные `events.jsonl`, `session.log`, `config.json`, а не только скопированный вывод терминала. Проверить сохранение файлов до ухода. Коммит пользователь выбирает и делает самостоятельно.
