# Yahboom 4WD Navigation

Учебный проект навигации четырёхколёсного робота Yahboom на Raspberry Pi: обнаружение неподвижного препятствия, экспериментальный объезд и восстановление общего направления движения.

## Текущая версия

Версия подготовлена по результатам испытаний 6 и 13 октября 2026 года. Непрерывный прямой ход проверен на роботе. Новый поэтапный объезд проверен программно и в симуляции; аппаратное испытание этой схемы ещё предстоит.

Исходная облачная копия `main2.py` сохранена без изменений под именем `robot_navigation.py` в [первом коммите](https://github.com/resassance/yahboom-4wd-navigation/commit/8c1a9b3a99447a3b6b8bac0c2895e122af91cc3a). Перед установкой нужно сохранить программу, находящуюся на самом роботе, и сравнить версии.

План двухчасового занятия, необходимые вещи, команды и таблицы замеров: [LAB_TEST_PLAN.md](LAB_TEST_PLAN.md).

Для нового занятия: [короткая инструкция на 13 октября](LAB_2026-10-13.md) и [описание локальных изменений](LOCAL_CHANGES_2026-10-13.md).

После выявления рывков на занятии подготовлено [обновление непрерывного хода](UPDATE_CONTINUOUS_DRIVE.md). Оно заменяет прежний архив `safe-servo`, сохраняя пределы датчика 45–135°. Исправление проверено на имитации GPIO; физический проезд нужно повторить.

После подтверждения нормального прямого хода подготовлен [поэтапный объезд](UPDATE_STAGED_BYPASS.md). Он заменяет предыдущий алгоритм выбора стороны и возврата; диапазон датчика и непрерывный ход сохранены. Обоснование, разбор журналов и ограничения: [BYPASS_DESIGN.md](BYPASS_DESIGN.md). Это текущая версия для следующего испытания.

## Что изменилось

- Для каждой пробы дальномера выполняется одно измерение. Медиана рассчитывается при наличии хотя бы трёх достоверных проб из пяти. При недостатке проб по умолчанию выполняется одна повторная серия на том же угле; окончательная неудача даёт неизвестное расстояние, а не свободный путь.
- В `auto` прямой ход непрерывен: моторы остаются включёнными между проверками расстояния. Перед стартом используется медиана пяти проб, во время движения — каждый свежий замер без ожидания серии. При расстоянии на уровне порога или ниже робот тормозит перед обзором. Сбой дальномера останавливает движение; повторные серии возможны только на неподвижном корпусе. `step_seconds` теперь задаёт интервал между проверками, а не импульс с торможением. Обзор и проверка направления возврата выполняются с остановкой. Ручные режимы `drive` и `turn` остаются ограниченными по времени с торможением в конце.
- Обзор состоит из девяти направлений внутри настроенных механических границ, по умолчанию 45–135°. Лучи, смотрящие на фронтальное препятствие, больше не запрещают весь боковой сектор. По внешним направлениям выбирается сторона пробного поворота; этот выбор разрешает только вращение с проверкой зазора, а не проезд.
- Перед поворотом проверяется запас пространства с учётом измеренных длины, ширины и положения датчика. Размеры предстоит внести в конфигурацию; без них автоматический режим не запускается.
- Корпус поворачивается боком к исходному курсу двумя командами по 45°, с новым обзором между ними. Перед боковым проездом проверяется коридор шириной робота плюс запас, учитывая смещение дальномера относительно центра корпуса. Поездка в сторону продолжается с фронтальным контролем и периодическими обзорами.
- Для возврата робот на месте поворачивает корпус обратно по 45° и снова осматривается. На исходном направлении нужны две полные проверки свободного коридора шириной робота до `resume_distance_cm`. При закрытом проходе корпус возвращается к боковому направлению через проверенные повороты, и объезд продолжается. Разрешение проверяется свежими обзорами; дальномер не выходит за 45–135°.
- Если боковой путь перекрыт, выполняется досрочная проверка исходного курса. Если оба пути закрыты либо достигнут предел шагов, робот останавливается для разбора ситуации. Задний ход и поиск сложного маршрута в этой версии не реализованы.
- Записываются исходные и обработанные измерения, ИК-входы, положения сервопривода, команды приводам, длительности, решения, состояния, ошибки и завершение.
- Камера включается отдельно. Один поток захватывает кадры для всех зрителей, события камеры попадают в журнал.
- Режим `plan` показывает решение алгоритма после обзора, не включая движение колёс.
- Режим `ir` опрашивает выбранные GPIO без инициализации приводов, камеры и сервопривода и считает изменения входных уровней.
- Мощность левого и правого приводов для прямого проезда можно подстроить раздельно. Повороты используют прежний PWM.

Распиновка и исходные значения PWM 25 для движения и 10 для поворота сохранены. Цветовые классы препятствий, коррекция по стенам и датчик напряжения пока не добавлены.

## Распиновка

Используется `GPIO.BCM`. Эти номера не являются физическими номерами контактов разъёма. Схема сохранена из рабочей копии пользователя и должна проверяться по фактическому подключению.

| Назначение | GPIO BCM |
| --- | --- |
| IN1 / IN2 / IN3 / IN4 | 20 / 21 / 19 / 26 |
| ENA / ENB | 16 / 13 |
| Ультразвуковой датчик: Echo / Trig | 0 / 1 |
| Сервопривод | 23 |
| Левый / правый ИК-датчик | 12 / 17 |
| RGB: красный / зелёный / синий | 22 / 27 / 24 |
| Кнопка | 8 |

Кнопка пока не управляет запуском. Углы сервопривода предполагаются такими же, как в исходнике: 0° — вправо, 90° — вперёд, 180° — влево. Команда положительного поворота означает поворот корпуса вправо. Это нужно проверить до автономного движения.

## Подготовка и запуск

На Raspberry Pi нужны Python 3.7 или новее и рабочая `RPi.GPIO`. Для видеопотока дополнительно нужны `Flask` и `cv2`, камера с индексом `0`. Без `--video` они не импортируются и камера не открывается. Используйте уже настроенное окружение робота с доступом к GPIO.

```bash
git clone https://github.com/resassance/yahboom-4wd-navigation.git
cd yahboom-4wd-navigation
python3 robot_navigation.py --mode distance --cycles 10
python3 robot_navigation.py --mode scan
```

Запуск без аргументов выполняет один неподвижный обзор. Для движения нужно явно выбрать режим:

```bash
python3 robot_navigation.py --mode turn --turn-deg 45
python3 robot_navigation.py --mode turn --turn-deg -45
python3 robot_navigation.py --mode drive --drive-seconds 0.5
```

Эти два режима служат для ручной калибровки на свободной площадке: автоматического разрешения по дальномеру в них нет. При проверенных ИК-датчиках можно включить их защиту флагом `--use-ir`.

Создать локальную копию настроек и заполнить измеренные значения в сантиметрах:

```bash
cp robot_config.json robot_config.local.json
```

- `robot_width_cm`: максимальная ширина, включая колёса и выступающие части.
- `robot_length_cm`: максимальная длина.
- `sensor_forward_offset_cm`: продольное расстояние от центра измеренного прямоугольника корпуса до излучателя дальномера; впереди центра — положительное, позади — отрицательное.
- `turn_right_deg_per_sec` и `turn_left_deg_per_sec`: измеренный угол / фактическая длительность команды для соответствующей стороны. Исходные 60°/с — прежняя оценка, требующая проверки.
- `left_drive_trim_pwm` и `right_drive_trim_pwm`: поправки к `move_speed` только для прямого движения, исходно 0. При настройке менять одну поправку на 1–2 пункта и повторять одинаковый проезд. Это ручная подстройка, фактический курс она не измеряет.
- `measurement_retries`: число повторных серий после недостатка достоверных проб, исходно 1. Можно задать 0–2.
- `servo_min_deg` / `servo_max_deg`: разрешённые углы поворота ультразвукового датчика, исходно 45/135. За их пределами команда отклоняется до PWM. Они действуют и для промежуточных положений, обзора и возврата.

Ограничение поворота корпуса до 18° отменено. Теперь исходное направление проверяется после пробных поворотов самого корпуса, поэтому возвратный веер не нужно помещать у края обзора датчика. При стандартных границах используются шаги корпуса по 45° до бокового направления ±90°. Физический угол по-прежнему оценивается по времени, а не измеряется. `max_escape_angle_deg` по умолчанию 90°; меньший предел не разрешает этот боковой объезд. `min_bypass_steps` (4) задаёт частоту обзора прохода, `return_probe_steps` (8) — интервал между пробами возврата после фактических шагов движения. Максимум шагов всего объезда остаётся 30. При отсутствии новых полей в старом конфиге используются эти значения по умолчанию.

Проверить решение при неподвижном корпусе после внесения смещения датчика:

```bash
python3 robot_navigation.py --config robot_config.local.json --mode plan --max-seconds 60
```

В событии `navigation_plan` выводятся предполагаемое действие `forward`/`turn`/`stop`, угол и причина. Колёса в этом режиме не включаются.

```bash
python3 robot_navigation.py --config robot_config.local.json --mode auto --max-seconds 60
```

`--max-seconds` ограничивает время после инициализации во всех режимах, по умолчанию 30 секунд. Во время сканирования этот срок тоже расходуется. `Ctrl+C` и `SIGTERM` запрашивают остановку; обработчики завершают текущую операцию и отключают PWM. Аппаратного аварийного выключателя код не заменяет.

Проверить ИК-входы можно в неподвижном режиме `distance`: подносить объект к каждому датчику и смотреть события `ir_reading`. Защита выключена по умолчанию, поскольку размещение и полярность ещё не подтверждены. После проверки указать `ir_active_level` (0 или 1) и запускать с `--use-ir`. Если датчики смотрят на пол, их сигналы нельзя использовать как достоверные признаки боковых препятствий.

Для видеопотока добавить `--video` и открыть `http://<IP-адрес-робота>:8080/` в той же сети. В браузере доступно только наблюдение. Сервер работает на время запуска программы; видео автоматически не сохраняется. Отказ камеры записывается отдельно и не отключает исправный дальномер. Первые проверки стоит выполнить без камеры, чтобы сравнить поведение без её нагрузки.

Для отдельной диагностики ИК без движения сервопривода:

```bash
python3 robot_navigation.py --mode ir --ir-pins 12,17 --max-seconds 30
python3 robot_navigation.py --mode ir --ir-pins 3,5,4,18 --max-seconds 30
```

Второй набор — предполагаемые входы четырёх датчиков линии по примерам; проверить соответствие фактической сборке. Поле `levels` показывает GPIO и сырые 0/1, `transitions` считает смены уровней. Выбранные входы настраиваются как GPIO.IN. Режим не управляет остановкой по линии и не меняет входы защиты режима `auto`. Не запускать одновременно с другой программой, управляющей GPIO.

## Журналы

Каждый запуск создаёт отдельную папку `logs/ГГГГММДД-ЧЧММСС-микросекунды/` рядом с программой:

- `events.jsonl`: все события, по одной записи JSON на строку; порядковый номер, время UTC и время от начала запуска.
- `session.log`: те же события в текстовом виде. Исходные пробы тоже записаны сюда, но не выводятся в терминал.
- `config.json`: точные настройки данного запуска.

В `session_start` есть режим, аргументы, версия Python и SHA-256 двух файлов программы. В `distance_raw` — угол, номер попытки и пробы, время импульса и причина неудачного измерения; в `distance_filtered` — весь набор проб и результат фильтра. `measurement_retry` отмечает повтор. `motor_start` содержит отдельные PWM колёс. `motor_stop` содержит фактическую длительность команды, а не измеренный угол корпуса. Оценка направления в событиях `state` остаётся расчётной. В режиме `ir` используются `ir_snapshot` и итоговая сводка `ir_monitor_summary`.

Логи сбрасываются в файлы после каждой строки, но внезапное отключение питания всё равно может потерять последние записи. Папка логов и `robot_config.local.json` исключены из Git. После занятия скопируйте их на ноутбук и сохраните вместе с таблицей испытаний, фотографиями и видео. Обновлённые общие параметры после проверки можно перенести в `robot_config.json` отдельным коммитом.

## Ограничения этой итерации

Девять лучей дальномера дают дискретные измерения: тонкие препятствия, углы и пространство сзади могут остаться незамеченными. Проверка габаритов — предварительная оценка по расширенной окружности корпуса, а не полная карта пространства. Возврат проверяется веером из трёх лучей и тоже требует испытаний на реальном препятствии. Более плотный обзор занимает больше времени, во время него робот стоит.

Разворот на месте и проезд по времени зависят от покрытия, проскальзывания и состояния питания. Измерителя фактического курса в этой версии нет. Возвращается оценка направления; прежняя линия пути не восстанавливается. Универсальный объезд любой неизвестной геометрии и гарантия отсутствия столкновений пока не достигнуты. Для первого занятия важны измерения, повторяемость и понятные причины остановки.

Ультразвук опрашивается программно через GPIO; нагрузка ОС может исказить длительность короткого импульса. Журналы помогут отделить сбои измерений от выбора манёвра и неточности приводов.

## Проверка дома

```bash
python3 robot_navigation.py --help
```

Локально пройдены 87 проверок, включая геометрическую симуляцию, обработку пропусков и выбросов, выбор стороны, габариты, этапы возврата, предел объезда, таймауты Echo, торможение при исключениях и остановке, режим без движения и журналы. Проверочные файлы хранятся локально и не входят в репозиторий. Они не подтверждают реальную распиновку, работу сервопривода, точность поворота или проходимость маршрута.

## Дальнейшая работа

Подготовка дома → испытания и замеры в вузе → сохранение кода и результатов → разбор журналов дома → следующая доработка. После проверки основы: размещение ИК-датчиков, измерения до стен и коррекция курса, красные/синие препятствия по цвету, исследование датчика напряжения.
