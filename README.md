# Yahboom 4WD Navigation

Навигация четырёхколёсного робота Yahboom на Raspberry Pi: обнаружение препятствий ультразвуковым датчиком, поэтапный объезд с запоминанием пути и приблизительным возвратом на исходную линию и распознавание красного и синего через камеру.

## Возможности

- Непрерывное движение вперёд с контролем расстояния. При препятствии на расстоянии `safe_distance_cm` или ближе робот останавливается и осматривается.
- Обзор в пяти направлениях: **45°, 68°, 90°, 112°, 135°**. Датчик поворачивается в пределах **45–135°**, центральное положение — 90°.
- Циклический объезд с учётом габаритов корпуса: повороты по 45°, непрерывный боковой проезд и возврат к исходному направлению. Новое препятствие вызывает торможение и выбор дальнейшего пути, сохраняя работу программы.
- Отдельный режим распознавания **красного и синего** без движения колёс и сервопривода.
- Видеопоток Flask для браузера. Один захват камеры используется для распознавания и всех зрителей.
- Журналы расстояний, команд моторам, углов датчика, решений навигации, результатов распознавания и ошибок.

В последнем обновлении убрано завершение `auto` при перекрытом боковом пути и после трёх попыток возврата. Робот продолжает искать доступное направление или ждёт открытия прохода до общего таймера. Память неудачных направлений предотвращает повторение того же манёвра без нового проезда или устойчивого изменения обстановки.

## Результаты проверки на роботе 10 ноября

Автоматический объезд с возвратом на линию пока не подтверждён реальными испытаниями. В двух заездах робот остановился перед первым поворотом, в третьем выполнил один поворот на 45° и перешёл в ожидание: луч 135° показывал около 6,2 см при требуемом запасе 10,8 см для вращения. Повторные обзоры не означают разрешения двигаться; моторы остаются выключенными, пока геометрическая проверка не разрешит манёвр.

При пороге 10 см зафиксирована слишком поздняя остановка: после неё центральный луч в одном опыте показывал около 4,85 см. Более раннее торможение с сохранением места для поворота ещё требует доработки. Уменьшать геометрический запас ради продолжения движения нельзя. В ручных проверках команда 45° длилась около 0,75 с, но фактический угол оценивался примерно в 40°; параметры поворота пока не перекалиброваны. Небольшой уход влево при одинаковых PWM также требует измерения и подбора раздельных поправок.

Входы датчиков препятствий — BCM 12/17. В отдельной проверке BCM 12 оставался равным 0; левый датчик расположен снизу и может реагировать на пол. BCM 17 переключался при предъявлении как красного, так и синего образца. Эти данные подтверждают реакцию правого входа, но не различение материалов. Перед калибровкой оба датчика должны быть установлены в рабочем положении для обнаружения препятствия, затем проверены по отдельности. Таблица материалов оставлена пустой.

## Требования

- Raspberry Pi с Linux и Python 3.7 или новее.
- `RPi.GPIO` для приводов и датчиков.
- OpenCV (`cv2`), NumPy и Flask для камеры.
- Камера с индексом `0` и доступ к роботу по SSH.

Для режима `color` доступ к GPIO не нужен. Камера включается автоматически в `color` или флагом `--video` в остальных совместимых режимах. Используйте настроенное окружение робота; если для GPIO или камеры нужны права администратора, запускайте команды с `sudo python3`.

## Установка

```bash
git clone https://github.com/resassance/yahboom-4wd-navigation.git
cd yahboom-4wd-navigation
cp robot_config.json robot_config.local.json
```

Для обновления существующей копии:

```bash
git pull --ff-only
```

Перед заменой файлов сохраните свою рабочую версию. При ручном переносе копируйте вместе `robot_navigation.py`, `navigation.py`, `trajectory.py`, `robot_config.json`, `color_detection.py` и `color_config.json`. Локальные параметры робота храните в `robot_config.local.json`. В старом локальном конфиге `safe_distance_cm` мог остаться равным 20; для нового порога явно установите 10.

## Режимы запуска

| Режим | Назначение |
| --- | --- |
| `distance` | Измерение расстояния перед роботом |
| `scan` | Обзор без движения колёс; режим по умолчанию |
| `plan` | Обзор и вывод решения навигации без движения колёс |
| `ir` | Чтение сырых уровней выбранных ИК-входов без инициализации приводов и сервопривода |
| `turn` | Поворот корпуса на заданный угол по времени |
| `drive` | Прямой проезд заданной длительности |
| `auto` | Движение с обнаружением препятствия и объездом |
| `color` | Распознавание цвета и видеопоток без инициализации GPIO |

Расстояние, обзор и решение навигации:

```bash
python3 robot_navigation.py --mode distance --cycles 10
python3 robot_navigation.py --mode scan
python3 robot_navigation.py --config robot_config.local.json --mode plan --max-seconds 20
```

Короткие команды движения:

```bash
sudo python3 robot_navigation.py --mode turn --turn-deg 45
sudo python3 robot_navigation.py --mode turn --turn-deg -45
sudo python3 robot_navigation.py --mode drive --drive-seconds 0.5
```

Положительный угол означает поворот корпуса вправо, отрицательный — влево. В `turn` и `drive` нет автоматического разрешения движения по дальномеру; эти режимы предназначены для ручной калибровки на свободной площадке.

Автономное движение:

```bash
sudo python3 robot_navigation.py --config robot_config.local.json --mode auto --obstacle-mode bypass --max-seconds 120
```

`--max-seconds` задаёт предельную длительность после инициализации: по умолчанию 30 секунд, максимум 600. Остановка — `Ctrl+C`. Завершение программы отключает PWM приводов.

`--obstacle-mode bypass` — обычный объезд по ультразвуку без классификации ИК, выбран по умолчанию. `--obstacle-mode ir` — выбор объезда или продавливания по настроенной ИК-классификации. Ультразвуковой контроль сохраняется в обоих вариантах. Отдельная защита `--use-ir` на BCM 12/17 включается независимо.

## Как проходит объезд

Перед препятствием робот останавливается и выбирает сторону по обзору. Корпус разворачивается на 90° двумя командами по 45°; между ними выполняется обзор места для следующего поворота. После оценки коридора для всего корпуса начинается непрерывный боковой проезд.

Отрезок проезда по умолчанию длится до **1,5 секунды фактической работы моторов вперёд**. Паузы, обзоры и повороты в это время не входят. Во время проезда дальномер направлен вперёд. Новое препятствие немедленно прерывает движение и запускает возврат к исходному направлению либо выбор другого пути. Недостоверное расстояние переводит робота в неподвижное ожидание новых измерений. Длительность отрезка не заставляет робота двигаться в препятствие.

Во время бокового объезда через каждые 0,4 секунды работы моторов выполняется остановка и обзор ширины прохода: один центральный луч может не заметить помеху на пути угла корпуса. После свободного обзора продолжается тот же отрезок, без обнуления накопленного времени. Обычный прямой ход по исходному направлению остаётся непрерывным.

После полного отрезка или препятствия на боковом пути робот останавливается, восстанавливает исходное направление обратными поворотами и осматривает коридор. Если проход закрыт, робот продолжает двигаться в прежнюю сторону при наличии места либо выбирает другую сторону. Смена стороны выполняется последовательными поворотами через исходное направление, с новым обзором между командами.

Свободный проход на 30 см запускает этап возврата на линию. Робот продолжает проезд вдоль препятствия по исходному направлению до `return_probe_seconds` работы моторов, затем поэтапно поворачивается внутрь объезда. Проверяется коридор шириной с диаметр вращения корпуса плюс запас: требуется место не только для проезда, но и для последующего разворота. Глубина проверки — минимум 30 см, а при заданной скорости — не меньше расчётного пути до линии с запасом на корпус и поворот. Если проход обратно закрыт, робот пытается восстановить исходное направление и продолжить поиск дальше вдоль препятствия. Каждый поворот разрешается отдельным обзором. Если места для поворота нет, робот ждёт; слепого возврата назад нет.

При свободном обратном коридоре робот компенсирует накопленное боковое смещение. Этот участок выполняется короткими проездами с остановками для замеров; полный обзор повторяется через 0,4 секунды работы моторов. После компенсации робот восстанавливает исходное направление и проверяет свободный проход на 30 см. Только затем регистрируется завершение объезда и продолжается обычное движение.

Препятствие, недостоверный замер или ИК-защита прерывают возврат, сохраняя его цель. Повороты и прямые участки хранятся в памяти текущего запуска и в журнале. После перезапуска незавершённый маршрут автоматически не восстанавливается.

Неудачный путь запоминается. Новая попытка допускается после дополнительного проезда длительностью от 0,3 секунды работы моторов либо устойчивого изменения измерений. Повороты и сканирования не считаются продвижением. Изменение обстановки сопоставляется только для одинакового направления корпуса; единичный скачок расстояния не сбрасывает память. Эти интервалы — программные признаки движения, а не измеренная дистанция.

Если доступного пути или места для вращения нет, моторы остаются выключенными. Робот делает паузу и повторяет обзор; появившийся проход позволяет продолжить движение. Это часть действующего цикла. Ограничение трёх попыток больше не завершает программу. Штатное завершение задаётся `--max-seconds` или `Ctrl+C`; ошибки оборудования также отключают моторы. После прерванного ИК-защитой поворота фактический угол неизвестен, поэтому автоматическое движение не возобновляется до окончания запуска.

## Распознавание цвета

```bash
python3 robot_navigation.py --mode color --max-seconds 120 --log-dir "$HOME/yahboom-color-logs"
```

Откройте `http://<IP-адрес-робота>:8080/` в браузере ноутбука в той же сети. В кадре отображаются область распознавания, рамка цветного объекта и результат:

- `RED` — красный;
- `BLUE` — синий;
- `UNKNOWN` — нет однозначного результата.

Параметр `--log-dir` в этой команде сохраняет журналы в домашнюю папку. Это позволяет запускать цветовой режим обычным пользователем, если папка `logs` рядом с программой была создана предыдущим запуском через `sudo`. Доступ к самой камере зависит от прав на устройство.

Цвет выделяется по HSV в центральной области кадра. Анализ выполняется до 5 раз в секунду на изображении шириной до 320 пикселей. Для подтверждения нужны три последовательных обработанных кадра одного цвета. При исчезновении цвета или появлении обоих цветов результат сбрасывается в `UNKNOWN`. Мелкие разрозненные пятна не суммируются в один объект.

Параметры находятся в `color_config.json`:

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `fps` | `5` | Максимальная частота анализа |
| `width` | `320` | Максимальная ширина изображения для анализа |
| `roi` | `[0.15, 0.15, 0.85, 0.75]` | Область `[x0, y0, x1, y1]` в долях ширины и высоты кадра |
| `min_area_ratio` | `0.04` | Минимальная доля площади одного связного цветного пятна внутри области |
| `min_saturation` / `min_value` | `100` / `60` | Нижние границы насыщенности и яркости |
| `confirm_frames` | `3` | Число последовательных кадров для подтверждения |
| `red_hue_ranges` | `[[0, 10], [170, 179]]` | Два диапазона красного на шкале оттенка OpenCV 0–179 |
| `blue_hue_range` | `[95, 130]` | Диапазон синего |

Нижняя четверть кадра исключена из области распознавания, чтобы уменьшить влияние пола и подсветки робота. Цветная поверхность должна находиться внутри рамки области. Пороги зависят от освещения и изображения камеры.

Для отдельного файла настроек:

```bash
python3 robot_navigation.py --mode color --color-config color_config.json --max-seconds 120
```

Распознавание через камеру служит для наблюдения. В `auto` тип препятствия определяется отдельной калибруемой ИК-классификацией; результат HSV не управляет движением.

## Камера

В остальных режимах видеопоток включается флагом `--video`, например:

```bash
sudo python3 robot_navigation.py --config robot_config.local.json --mode auto --video --max-seconds 120
```

Адрес — `http://<IP-адрес-робота>:8080/`. Порт можно изменить через `--port`. Браузер показывает изображение; управление движением выполняется через программу.

Кадры кодируются в памяти. **Автоматического сохранения фотографий и видео нет.** Не запускайте одновременно другую программу, использующую ту же камеру.

Камера открывается через Linux V4L2 со штатным форматом устройства, без автоматического выбора GStreamer. Сначала программа получает первый кадр и только затем запускает веб-страницу и общий фоновый захват. Отдельного пятисекундного ограничения на первый кадр нет. События `camera_opening`, `camera_import_ready`, `camera_open` и `camera_first_frame_start` показывают этап запуска; в `camera_open` указан используемый backend.

Если камера не открылась, запуск прерывается. При отказе во время работы видеопоток завершается, а программа возвращает ненулевой код завершения. В `color` отказ завершает режим сразу после обнаружения; при дополнительном `--video` навигация продолжает работать до своего завершения или остановки.

## Настройки движения

В `robot_config.json` указаны параметры текущей сборки. Для своих значений используйте `robot_config.local.json` и передавайте его через `--config`.

| Параметр | Значение | Назначение |
| --- | --- | --- |
| `safe_distance_cm` | `10` | Расстояние остановки перед препятствием |
| `resume_distance_cm` | `30` | Глубина свободного прохода для возврата к исходному направлению |
| `clearance_margin_cm` | `5` | Запас пространства вокруг корпуса |
| `robot_length_cm` / `robot_width_cm` | `24` / `18.5` | Габариты корпуса, см |
| `sensor_forward_offset_cm` | `11` | Смещение излучателя вперёд относительно центра корпуса, см |
| `move_speed` / `turn_speed` | `25` / `10` | PWM прямого движения и поворота |
| `left_drive_trim_pwm` / `right_drive_trim_pwm` | `0` / `0` | Раздельные поправки PWM для прямого движения |
| `turn_right_deg_per_sec` / `turn_left_deg_per_sec` | `60` / `60` | Расчётная скорость поворота корпуса |
| `servo_min_deg` / `servo_max_deg` | `45` / `135` | Границы поворота дальномера |
| `max_escape_angle_deg` | `90` | Максимальное отклонение корпуса при боковом объезде |
| `bypass_segment_seconds` | `1.5` | Длительность каждого бокового отрезка по времени работы моторов, с |
| `retry_pause_seconds` | `1.0` | Пауза перед повторным обзором при отсутствии пути, с |
| `min_return_progress_seconds` | `0.3` | Дополнительное время проезда для повторной попытки ранее закрытого направления, с |
| `bypass_observation_seconds` | `0.4` | Интервал между обзорами ширины прохода при боковом движении, по времени работы моторов, с |

`bypass_segment_seconds`, `retry_pause_seconds` и `min_return_progress_seconds` допускают значения от 0,1 до 10 секунд. Ширина 18,5 см и длина 24 см заданы также как значения по умолчанию в программе. Старые локальные конфиги загружаются с новыми значениями по умолчанию. Поля `min_bypass_steps`, `return_probe_steps`, `max_bypass_steps`, `clear_checks_to_resume` и `max_return_attempts` сохранены для чтения старых файлов, но больше не задают ход манёвра.

`bypass_observation_seconds` допускает значения от 0,1 до 1 секунды. Более редкий обзор увеличивает промежуток движения с одним фронтальным лучом. Пять направлений дальномера дают дискретные измерения и не покрывают пространство между лучами или позади корпуса.

Ультразвуковые измерения в неподвижном положении объединяются медианой: нужны минимум три достоверные пробы из пяти. Во время прямого движения используется каждый свежий замер. Недостоверное расстояние останавливает движение; отсутствие измерения не считается свободным путём.

Угол корпуса и боковое смещение по умолчанию оцениваются по длительности работы моторов. Паузы и сканирования не включаются в проезд. Учитываются знак и угол каждого участка; при возврате компенсируется сумма боковых смещений. Покрытие, проскальзывание, повороты и питание влияют на результат: возврат на линию приблизительный, коррекции курса по боковым стенам пока нет. Пространство сзади не измеряется; задний ход и поиск сложного маршрута не реализованы.

### Параметры памяти пути

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `return_probe_seconds` | `1.5` | Проезд вдоль препятствия между попытками найти проход к исходной линии, 0,1–10 с работы моторов |
| `return_tolerance_seconds` | `0.03` | Допуск остаточного бокового смещения в эквиваленте работы моторов, до 0,1 с; это не измеренная точность |
| `drive_speed_cm_s` | `null` | Измеренная линейная скорость при текущих PWM, покрытии и питании. Без неё смещения хранятся в секундах, сантиметры не выдумываются |
| `range_reference_heading_deg` | `null` | Направление заранее выбранной неподвижной стены относительно исходного курса; включает дополнительную оценку проезда по дальномеру только в этом направлении |

Для измерения скорости на свободной площадке отметьте положение робота, выполните `--mode drive --drive-seconds 1`, измерьте перемещение и разделите на фактическое время из `motor_stop`. Повторите несколько раз при тех же PWM и покрытии. Запишите полученную скорость в локальный конфиг. Не используйте оценку по величине PWM: это не сантиметры в секунду.

Поправка по ультразвуку выключена до явного выбора стены и задания измеренной скорости. На остановках сопоставляются центральный и соседние лучи 68°/112°: проверяется согласованность с плоской стеной поперёк выбранного направления. Разность расстояний допускается как поправка лишь при том же направлении, без промежуточных поворотов, и при согласовании с ожидаемым проездом. Пропуск, резкий скачок, рост расстояния или несогласованные лучи не исправляют память пути. После поворота опорный замер сбрасывается. Эти проверки не доказывают, что поверхность та же: включайте режим только для заранее выбранной неподвижной стены, остающейся в поле датчика. Это не автоматическое сопоставление произвольных объектов.

## Распиновка и ИК-входы

Используется нумерация **GPIO BCM**. Она отличается от физических номеров контактов разъёма.

| Назначение | GPIO BCM |
| --- | --- |
| IN1 / IN2 / IN3 / IN4 | 20 / 21 / 19 / 26 |
| ENA / ENB | 16 / 13 |
| Ультразвук: Echo / Trig | 0 / 1 |
| Сервопривод дальномера | 23 |
| Левый / правый ИК-вход | 12 / 17 |
| RGB: красный / зелёный / синий | 22 / 27 / 24 |
| Кнопка | 8 |

Распиновка соответствует текущей программе. Кнопка пока не управляет запуском. Углы дальномера: 45° — вправо, 90° — вперёд, 135° — влево.

Чтение выбранных ИК-входов:

```bash
sudo python3 robot_navigation.py --mode ir --ir-pins 12,17 --max-seconds 30
```

`levels` содержит сырые уровни 0/1, `transitions` — число смен уровня. Для защиты движения используется флаг `--use-ir` и параметр `ir_active_level`. Защита по умолчанию выключена: размещение и полярность датчиков зависят от сборки. Датчики, направленные на пол, не дают достоверного признака бокового препятствия.

## Классификация препятствий по ИК

В `auto` передний замер ультразвука сопровождается чтением ИК до и после измерения. Моторы при свободном пути продолжают работать. На расстоянии `forward_threshold()` или ближе робот останавливается. При текущих габаритах это 10 см; геометрический запас не уменьшен. Недостоверный замер также останавливает движение.

Группа классификации по умолчанию — BCM **12/17**: левый и правый датчики препятствий по распиновке Yahboom. BCM 3/5/4/18 относятся к нижней группе линии и не заменяют верхние датчики. На конкретной сборке соответствие нужно подтвердить отдельным воздействием на каждый верхний датчик. Защита `--use-ir` читает те же BCM 12/17; она сохраняет прежнее назначение и может запретить продавливание. Выбранные входы настраиваются через `ir_classification_pins` в конфиге. Контакты приводов, сервопривода, дальномера, кнопки и RGB зарезервированы.

До калибровки `ir_obstacle_patterns` пуст, рабочий диапазон не задан. Любое препятствие считается неизвестным и объезжается. Камера для этой логики не нужна.

Для калибровки используйте неподвижный режим:

```bash
sudo python3 robot_navigation.py --mode ir --ir-pins 12,17 --max-seconds 30
```

Отдельно предъявите красный образец, синий и фон без препятствия; запишите расстояние, положение образцов и уровни. Проверьте повторяемость в рабочем диапазоне и сопоставьте входы физическим датчикам. ИК реагирует на материал и расстояние, поэтому цвета нельзя заранее назначить уровням 0/1.

Параметры локальной конфигурации:

| Параметр | Назначение |
| --- | --- |
| `ir_classification_pins` | Порядок BCM-входов в каждом шаблоне, по умолчанию `[12, 17]` |
| `ir_obstacle_patterns` | Объект с ключами `dangerous` и/или `permitted`; значение каждого — измеренный массив 0/1 в порядке входов |
| `ir_background_pattern` | Измеренный массив уровней без препятствия; обязателен при заполненной таблице |
| `ir_min_distance_cm`, `ir_max_distance_cm` | Измеренные границы рабочего диапазона, до калибровки `null` |
| `ir_confirm_samples` | Число последовательных замеров после остановки, по умолчанию 3, допустимо 3–20 |
| `push_speed` | PWM обоих бортов при продавливании, по умолчанию 10; не выше 10 и обычной скорости |
| `push_seconds` | Лимит попытки, по умолчанию 0,3 с; увеличение сверх 0,3 запрещено |

Каждый замер классификации проверяет ИК до и после ультразвука. Все показания серии должны соответствовать одному типу, а все расстояния — рабочему диапазону. Сигнал BCM 3 записывается, но не определяет тип: шаблоны материалов и фона обязаны различаться на остальных выбранных входах. Совпадение с фоном, шум, неизвестный сигнал или неподходящая дистанция дают `unknown`. Автоматического сближения ради распознавания нет. Если на допустимой дистанции образцы и фон неразличимы, таблицу оставьте пустой.

В `--obstacle-mode ir` результаты `dangerous` и `unknown` запускают существующий объезд. Только `permitted` разрешает отдельную попытку продавливания с пересечением обычного порога остановки. Перед ней повторно проверяются дистанция и ИК-защита. Во время попытки продолжаются ограниченные по времени ультразвуковые измерения; недостоверные данные прекращают движение. Независимый таймер отключает моторы по лимиту даже при задержке основного цикла. Это программное ограничение, фактическое время и движение нужно проверить на роботе.

После попытки моторы останавливаются, выполняется полный обзор. Возобновление прямого хода требует свободного коридора на 30 см, а не одиночного увеличения дистанции. Закрытый путь запускает объезд, недостоверные измерения — ожидание. Повторное продавливание заблокировано до завершения объезда с новым проездом не менее `min_return_progress_seconds`. Если после попытки проход сразу открыт, блокировка сохраняется: следующий объект будет объезжаться до такого манёвра. Контроля усилия и заклинивания нет.

## Журналы

Каждый запуск создаёт папку `logs/ГГГГММДД-ЧЧММСС-микросекунды/` рядом с программой:

- `events.jsonl` — события в формате JSON, по одному на строку;
- `session.log` — текстовый журнал;
- `config.json` — параметры движения данного запуска;
- `color_config.json` — параметры распознавания, только в режиме `color`.

В `session_start` сохраняются аргументы, версия Python и SHA-256 файлов программы. События дальномера содержат исходные пробы и результат фильтрации; команды моторам — мощности и длительности; решения навигации — этап и причину действия или остановки.

`bypass_segment_start` отмечает новый боковой отрезок, `bypass_progress` — накопленное время проезда, `return_requested` — начало возврата после проезда или нового препятствия. `route_blocked` и `route_memory_updated` показывают запоминание и повторное открытие направлений. `return_deferred` отмечает отложенный повтор неудачного возврата; `route_selected` — новый выбор стороны; `navigation_wait` — ожидание доступного пути. В событиях манёвра есть выбранная сторона, расчётное направление, достоверность этой оценки, номер отрезка, время движения, номер попытки возврата и последнее фронтальное расстояние.

`path_memory_start`, `path_progress` и `path_turn` записывают начало запоминания, проезды и повороты; `path_range_correction` и `path_range_rejected` — принятие или отклонение поправки по выбранной стене. `trajectory_return_start`, `trajectory_cross_corridor`, `trajectory_cross_start` и `trajectory_return_wait` показывают этап возврата и его блокировки. `path_return_complete` означает завершение компенсации смещения и восстановление курса по расчётной модели, а не независимое измерение положения. `navigation_final` сохраняет итоговую оценку и историю участков, включая незавершённый манёвр.

`ir_obstacle_reading` содержит входы и уровни; `ir_obstacle_sample` — показания до/после замера и дистанцию; `obstacle_classification` — тип, устойчивость и причину. `obstacle_action` записывает выбор манёвра, `push_start`, `push_distance`, `push_end` — ход попытки и причину остановки, `push_assessment` — результат полного обзора.

В режиме цвета `color_result` записывается при смене результата и раз в пять секунд. Событие содержит доли цветов, причину, координаты рамки и время обработки. `camera_stats` раз в пять секунд показывает частоту захвата и число обработанных кадров. Покадровой записи в журнал нет.

Папка журналов и локальная конфигурация исключены из Git.
