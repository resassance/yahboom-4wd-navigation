# Yahboom 4WD Navigation

Учебный проект автономного движения четырёхколёсного робота Yahboom на Raspberry Pi: обнаружение неподвижных препятствий ультразвуковым датчиком, манёвр объезда и попытка возвращения к исходному направлению движения.

## Статус

В репозитории сохранена исходная версия программы из облачной копии `main2.py`. Файл переименован в `robot_navigation.py`; содержимое программы сохранено без изменений. Это отправная точка для дальнейшей отладки и экспериментов. Совпадение этой копии с программой, установленной на роботе, предстоит проверить.

Робот ранее испытывался на стенде, однако эта копия содержит известные ошибки и ограничения. Результаты новых испытаний и исправления будут фиксироваться отдельно.

## Что реализовано

- Управление левым и правым приводами через GPIO и PWM.
- Измерение расстояния ультразвуковым датчиком.
- Поворот датчика сервоприводом и сканирование направлений 0°, 45°, 90°, 135° и 180°.
- Выбор поворота при обнаружении препятствия и короткий проезд после поворота.
- Учёт заданных углов для попытки восстановления исходного направления.
- Видеопоток с камеры через Flask с наложением показаний и текущего решения.
- Запись отдельных событий в `logs.txt`.

Камера пока используется только для видеонаблюдения. ИК-датчики настроены как входы, но их показания не участвуют в принятии решений. Направление оценивается по командам поворота и времени их выполнения; фактический угол не измеряется.

## Оборудование и зависимости

- Робот Yahboom Raspberry Pi 4WD с подключёнными приводами.
- Raspberry Pi с Python 3 и поддержкой используемой библиотеки GPIO.
- Ультразвуковой датчик на сервоприводе.
- Камера, доступная OpenCV как устройство `0`.
- Python-библиотеки: `Flask`, `OpenCV` (`cv2`) и `RPi.GPIO`.

`threading` и `time` входят в стандартную библиотеку Python. Программа предназначена для запуска на роботе; на обычном компьютере аппаратные зависимости и устройства могут отсутствовать.

## Распиновка в сохранённой программе

Используется `GPIO.BCM`: номера GPIO не совпадают с физическими номерами контактов разъёма. Таблица описывает текущий код и должна сверяться с фактической сборкой робота.

| Назначение | GPIO BCM |
| --- | --- |
| IN1 / IN2 / IN3 / IN4 | 20 / 21 / 19 / 26 |
| ENA / ENB | 16 / 13 |
| Ультразвуковой датчик: Echo / Trig | 0 / 1 |
| Сервопривод | 23 |
| Левый / правый ИК-датчик | 12 / 17 |
| RGB: красный / зелёный / синий | 22 / 27 / 24 |
| Кнопка | 8 |

## Запуск

После подготовки зависимостей и подключения оборудования выполнить на Raspberry Pi:

```bash
python3 robot_navigation.py
```

При запуске программа сразу начинает автономное управление движением: ожидание кнопки старта в этой версии не реализовано. Процессу нужны права доступа к GPIO и камере.

В браузере устройства в той же сети открыть:

```text
http://<IP-адрес-робота>:8080/
```

Видеопоток также доступен по пути `/video_feed`. Для остановки программы в терминале используется `Ctrl+C`; обработчик завершения останавливает приводы, освобождает GPIO и камеру.

## Известные ошибки и ограничения

- В `Distance_test()` проверяется одно измерение, а в список записывается другое. При одном или двух отобранных значениях возможно деление на ноль.
- Если все проверенные направления перекрыты, `turn_deg` может оказаться неопределённым либо сохранить значение предыдущего манёвра.
- Свободное пространство перед роботом после поворота используется как основание для возвращения направления, хотя препятствие ещё может быть не пройдено.
- Выбор стороны имеет приоритет левого направления и не сравнивает полные маршруты объезда.
- Ширина корпуса и пространство, занимаемое машиной при развороте, не учитываются.
- Повороты выполняются по времени с постоянной оценкой 60°/с; фактическая точность зависит от условий движения.
- Для поворотов на 70° сообщение на экране и в журнале всё равно указывает 45°.

Это замечания по анализу сохранённого кода. Причины конкретных сбоев на стенде необходимо подтверждать измерениями и логами.

## Дальнейшая работа

1. Исправить ошибки обработки измерений и выбора манёвра; добавить диагностические логи.
2. Проверить размещение датчиков, задействовать ИК-датчики и исследовать измерения расстояний до боковых стен.
3. Доработать объезд с учётом габаритов и восстановление направления по результатам испытаний.
4. Добавить распознавание красных и синих препятствий по цвету без нейросетей.
5. Исследовать показания датчика напряжения и возможность учитывать их при движении.

Рабочий цикл: подготовка программы дома → испытания и замеры в вузе → сохранение кода и результатов → следующая доработка. Версии, проверенные на роботе, следует явно отмечать в истории проекта.
