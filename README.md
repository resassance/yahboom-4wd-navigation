# Yahboom 4WD Navigation

Учебный проект навигации четырёхколёсного робота Yahboom на Raspberry Pi: обнаружение неподвижного препятствия, экспериментальный объезд и восстановление общего направления движения.

## Текущая версия

Подготовлена к испытаниям 6 октября 2026 года. Исправления проверены на искусственных показаниях и подменённых устройствах; на настоящем роботе эта версия ещё не испытана.

Исходная облачная копия `main2.py` сохранена без изменений под именем `robot_navigation.py` в [первом коммите](https://github.com/resassance/yahboom-4wd-navigation/commit/8c1a9b3a99447a3b6b8bac0c2895e122af91cc3a). Перед установкой нужно сохранить программу, находящуюся на самом роботе, и сравнить версии.

План двухчасового занятия, необходимые вещи, команды и таблицы замеров: [LAB_TEST_PLAN.md](LAB_TEST_PLAN.md).

## Что изменилось

- Для каждой пробы дальномера выполняется одно измерение. Медиана рассчитывается при наличии хотя бы трёх достоверных проб из пяти. Таймауты и недостаток проб дают неизвестное расстояние, а не свободный путь.
- Измерения и сканирование выполняются после остановки приводов. Движение разбито на короткие импульсы с остановкой в конце каждого.
- Сторона выбирается по большему минимальному расстоянию в боковом и диагональном направлениях. При заблокированных или неизвестных направлениях робот останавливается.
- Перед поворотом проверяется запас пространства с учётом измеренных длины, ширины и положения датчика. Размеры предстоит внести в конфигурацию; без них автоматический режим не запускается.
- Возврат разрешается после минимального числа шагов объезда и двух последовательных проверок исходного направления с боковыми лучами. Перед обратным поворотом дополнительно проверяется пространство вокруг робота.
- Если путь объезда перекрыт или достигнут предел шагов, робот останавливается для разбора ситуации. Задний ход и поиск сложного маршрута в этой версии не реализованы.
- Записываются исходные и обработанные измерения, ИК-входы, положения сервопривода, команды приводам, длительности, решения, состояния, ошибки и завершение.
- Камера включается отдельно. Один поток захватывает кадры для всех зрителей, события камеры попадают в журнал.

Распиновка и исходные значения PWM 25 для движения и 10 для поворота сохранены. Цветовые классы препятствий, коррекция по стенам и датчик напряжения пока не добавлены.

## Распиновка

Используется `GPIO.BCM`. Эти номера не являются физическими номерами контактов разъёма. Схема сохранена из рабочей копии пользователя и должна проверяться по фактическому подключению.

| Назначение | GPIO BCM |
| --- | --- |
| IN1 / IN2 / IN3 / IN4 | 20 / 21 / 19 / 26 |
| ENA / ENB | 16 / 13 |
| Ультразвуковой датчик: Echo / Trig | 0 / 1 |
| Сервопривод | 23 |
| Левый / правый ИК-датчик | 12 / 17 |
| RGB: красный / зелёный / синий | 22 / 27 / 24 |
| Кнопка | 8 |

Кнопка пока не управляет запуском. Углы сервопривода предполагаются такими же, как в исходнике: 0° — вправо, 90° — вперёд, 180° — влево. Команда положительного поворота означает поворот корпуса вправо. Это нужно проверить до автономного движения.

## Подготовка и запуск

На Raspberry Pi нужны Python 3.7 или новее и рабочая `RPi.GPIO`. Для видеопотока дополнительно нужны `Flask` и `cv2`, камера с индексом `0`. Без `--video` они не импортируются и камера не открывается. Используйте уже настроенное окружение робота с доступом к GPIO.

```bash
git clone https://github.com/resassance/yahboom-4wd-navigation.git
cd yahboom-4wd-navigation
python3 robot_navigation.py --mode distance --cycles 10
python3 robot_navigation.py --mode scan
```

Запуск без аргументов выполняет один неподвижный обзор. Для движения нужно явно выбрать режим:

```bash
python3 robot_navigation.py --mode turn --turn-deg 45
python3 robot_navigation.py --mode turn --turn-deg -45
python3 robot_navigation.py --mode drive --drive-seconds 0.5
```

Эти два режима служат для ручной калибровки на свободной площадке: автоматического разрешения по дальномеру в них нет. При проверенных ИК-датчиках можно включить их защиту флагом `--use-ir`.

Создать локальную копию настроек и заполнить измеренные значения в сантиметрах:

```bash
cp robot_config.json robot_config.local.json
```

- `robot_width_cm`: максимальная ширина, включая колёса и выступающие части.
- `robot_length_cm`: максимальная длина.
- `sensor_forward_offset_cm`: продольное расстояние от центра измеренного прямоугольника корпуса до излучателя дальномера; впереди центра — положительное, позади — отрицательное.
- `turn_right_deg_per_sec` и `turn_left_deg_per_sec`: измеренный угол / фактическая длительность команды для соответствующей стороны. Исходные 60°/с — прежняя оценка, требующая проверки.

```bash
python3 robot_navigation.py --config robot_config.local.json --mode auto --max-seconds 60
```

`--max-seconds` ограничивает время после инициализации во всех режимах, по умолчанию 30 секунд. Во время сканирования этот срок тоже расходуется. `Ctrl+C` и `SIGTERM` запрашивают остановку; обработчики завершают текущую операцию и отключают PWM. Аппаратного аварийного выключателя код не заменяет.

Проверить ИК-входы можно в неподвижном режиме `distance`: подносить объект к каждому датчику и смотреть события `ir_reading`. Защита выключена по умолчанию, поскольку размещение и полярность ещё не подтверждены. После проверки указать `ir_active_level` (0 или 1) и запускать с `--use-ir`. Если датчики смотрят на пол, их сигналы нельзя использовать как достоверные признаки боковых препятствий.

Для видеопотока добавить `--video` и открыть `http://<IP-адрес-робота>:8080/` в той же сети. В браузере доступно только наблюдение. Сервер работает на время запуска программы; видео автоматически не сохраняется. Отказ камеры записывается отдельно и не отключает исправный дальномер. Первые проверки стоит выполнить без камеры, чтобы сравнить поведение без её нагрузки.

## Журналы

Каждый запуск создаёт отдельную папку `logs/ГГГГММДД-ЧЧММСС-микросекунды/` рядом с программой:

- `events.jsonl`: все события, по одной записи JSON на строку; порядковый номер, время UTC и время от начала запуска.
- `session.log`: те же события в текстовом виде. Исходные пробы тоже записаны сюда, но не выводятся в терминал.
- `config.json`: точные настройки данного запуска.

В `session_start` есть режим, аргументы, версия Python и SHA-256 двух файлов программы. В `distance_raw` — угол, номер пробы, время импульса и причина неудачного измерения; в `distance_filtered` — весь набор проб и результат фильтра. `motor_stop` содержит фактическую длительность команды, а не измеренный угол корпуса. Оценка направления в событиях `state` остаётся расчётной.

Логи сбрасываются в файлы после каждой строки, но внезапное отключение питания всё равно может потерять последние записи. Папка логов и `robot_config.local.json` исключены из Git. После занятия скопируйте их на ноутбук и сохраните вместе с таблицей испытаний, фотографиями и видео. Обновлённые общие параметры после проверки можно перенести в `robot_config.json` отдельным коммитом.

## Ограничения этой итерации

Пять лучей дальномера дают редкие измерения: тонкие препятствия, углы и пространство сзади могут остаться незамеченными. Проверка габаритов — предварительная оценка по расширенной окружности корпуса, а не полная карта пространства. Возврат проверяется веером из трёх лучей и тоже требует испытаний на реальном препятствии.

Разворот на месте и проезд по времени зависят от покрытия, проскальзывания и состояния питания. Измерителя фактического курса в этой версии нет. Возвращается оценка направления; прежняя линия пути не восстанавливается. Универсальный объезд любой неизвестной геометрии и гарантия отсутствия столкновений пока не достигнуты. Для первого занятия важны измерения, повторяемость и понятные причины остановки.

Ультразвук опрашивается программно через GPIO; нагрузка ОС может исказить длительность короткого импульса. Журналы помогут отделить сбои измерений от выбора манёвра и неточности приводов.

## Проверка дома

```bash
python3 -m unittest discover -s tests -v
python3 robot_navigation.py --help
```

Тесты проверяют обработку пропусков и выбросов, выбор стороны, габариты, этапы возврата, предел объезда, таймауты Echo, торможение при исключениях и остановке, режим без движения и журналы. Они не подтверждают реальную распиновку, работу сервопривода, точность поворота или проходимость маршрута.

## Дальнейшая работа

Подготовка дома → испытания и замеры в вузе → сохранение кода и результатов → разбор журналов дома → следующая доработка. После проверки основы: размещение ИК-датчиков, измерения до стен и коррекция курса, красные/синие препятствия по цвету, исследование датчика напряжения.
